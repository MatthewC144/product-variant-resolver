# Specification Index

Specifications are versioned decision contracts, not a backlog where every unchecked historical
task remains current. Each feature directory may contain requirements, design, tasks, approvals,
and a QA review produced under the Lite/Lean workflow.

## Current portfolio and repository contracts

- `repository-hygiene-cleanup-v1/` — current GitHub organization cleanup.
- `repository-readability-cleanup-v1/` — public reading path and claim hierarchy.
- `portfolio-release-closure-v1/` — latest full release verification.
- `serper-dual-source-evaluation-v1/` — primary paired-source ranking result.
- `serper-dual-source-policy-calibration-v1/` — source-matched calibration shortfall.

## Historical feature specifications

All other directories are retained to explain how catalog ingestion, Human Knowledge, PostgreSQL,
authority review, Pointwise/Listwise experiments, hard-negative mining, calibration, and benchmark
governance evolved. Their task IDs such as CAR, RHB, T49, or DRV2 are lineage labels—not current
instructions for a new reader.

For outcomes, use [Results](../docs/RESULTS.md). For chronology, use the
[Project Log](../docs/PROJECT-LOG.md). Do not infer current runtime behavior from an old task file.
